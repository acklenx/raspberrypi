Reset & Recover a Board

When a Pico is "stuck" — running old code, ignoring your changes, throwing errors right after an update, or acting haunted on the network — work down this ladder from gentlest to most drastic. Stop at the first rung that fixes it. Every rung shows both the Viper IDE way (what a student does) and the mpremote way (command line).

Rung 1 · gentlest

Stop what's running

The board auto-runs main.py at every power-up, and it can't be edited while it runs. Halt it first.

Viper IDE

  1. Click Stop (the square) in the terminal panel.
  2. If it won't catch, click into the terminal and press Ctrl+C.
  3. You should land at the >>> prompt. Now you can edit and run.

mpremote

mpremote connect <port>   # Ctrl-C interrupts a running main.py
mpremote connect <port> soft-reset
Rung 2

Delete the stale compiled copy

A compiled .mpy file beats a source .py of the same name on import. So an old lib/picolab.mpy quietly overrides the fresh lib/picolab.py you just installed — that's the classic "TypeError right after an update." Delete the .mpy.

Viper IDE

  1. In the file panel, open the lib/ folder on the board.
  2. Delete any .mpy whose .py you're using (e.g. picolab.mpy, ssd1306.mpy).
  3. Re-run the project's one-click install to refresh the .py.

mpremote

mpremote connect <port> fs ls :lib
mpremote connect <port> fs rm :lib/picolab.mpy
Why this bites us: Viper's GitHub installer compiles .py to .mpy on the way in, so boards accumulate these. When in doubt, wipe them all (Rung 3).
Rung 3

Wipe the filesystem (keep the firmware)

Remove every user file — stale .mpy, old main.py, leftover wifi.json / name.txt / cal.json / placements.json, and any junk from past projects — back to bare MicroPython. Then reinstall clean. This is the reliable "make it behave" reset, and it fixes network weirdness by removing the old wifi.json (the board falls back to its own hotspot until you reinstall).

Viper IDE

  1. Open tools/wipe.py, paste it into a new file, click Run.
  2. It prints what it removed. The board is now empty.
  3. Re-install your project with its one-click link. Done, clean.

mpremote

mpremote connect <port> run tools/wipe.py
# then reinstall from Viper, or:
mpremote connect <port> mip install \
  github:acklenx/raspberrypi
Rung 4 · nuclear

Re-flash the firmware (true factory reset)

Wipes everything, the filesystem AND MicroPython itself, and lays down a known-good firmware. Use it when a board is truly unresponsive, or when you want a guaranteed-clean start. This is the one thing a browser can't do — the bootloader is a plain USB drive.

The BOOTSEL dance (about 15 seconds)

  1. Hold the BOOTSEL button while plugging the Pico into USB.
  2. It appears as a flash drive named RP2350.
  3. Drag on the exact tested firmware (.uf2).
  4. The drive vanishes, the board reboots into fresh MicroPython. Reinstall your project.

Software shortcut: from a working REPL, import machine; machine.bootloader() drops the board into BOOTSEL mode with no button press, ready for the drag-on.

The golden rule

Doubt what's on a board? Wipe it (Rung 3) and reinstall. Ten seconds of certainty beats an hour of chasing a ghost .mpy. And remember a finished board needs nothing but power: it runs main.py from flash on every boot and rejoins the network on its own.
