Pico 2 W Lab Guide

MicroPython samples and sensor demos for Maker Lab Kids workshops at WHS.

Code: github.com/acklenx/raspberrypi  ·  IDE: viper-ide.org

What this is

These are the MicroPython programs and the wiring for the Pico 2 W sensor stations used in the workshop. Every station has the same shape: a Pico 2 W, a small OLED screen, and one sensor (or a servo), wired on a breadboard. Each one runs a program that shows live readings on the screen and, in its web version, serves a live dashboard over its own Wi-Fi network. Learn one station and you know them all.

For every sensor below you get three things: the code to install in one click, the exact wiring, and a diagram. Start with the examples, build the stations, then point them at the worm bins.

Every session proves one new layer works before the next stacks on top of it. When something fails, you know it is the thing you just added.

Quickstart

  1. Flash MicroPython (one time per board). Hold the BOOTSEL button while plugging the Pico into USB. It shows up as a flash drive. Drag on the Pico 2 W firmware (.uf2): download the exact tested build (v1.28.0) from this repo, or the newest from micropython.org. The drive disappears and the board reboots into MicroPython.
  2. Open viper-ide.org in Chrome or Edge.
  3. Connect: click the connect button (top right), pick USB, choose the Pico.
  4. Upload files with the file panel, run them from the terminal panel.
  5. A file saved as main.py runs automatically every time the board powers up. That is how a finished project ships.

Every demo is fault tolerant

All the sensor demos follow the same house rules, so a missing part never sinks a lesson.

Display optional

Demos assume the OLED is there, but run fine without it, and pick it up within about 3 seconds when it gets plugged in.

Sensors hot-plug

Start with no sensor, plug it in whenever: readings appear within about 2 seconds. No restart, no reset button.

Terminal logging

A startup banner and the first readings print immediately, then a slow heartbeat line every 5 seconds keeps the terminal readable.

Built-in web dashboard

Web versions open a Wi-Fi network named PicoLab-N (N is remembered per board). Dashboard at http://192.168.4.1, raw JSON at /data.

The truth light

The onboard LED never lies: one short blink per part, in order, then a pause. Long blink = that part is in trouble. Five probes reading . . . _ . means probe 4 has a loose wire. Dark = code not running.

Everything at once, on ONE Pico: two BME280s (in/out), the DS18B20 probe array, two soil moistures and the light divider riding an ADS1115, the mic, the distance sensor, two servos, and a relay. Wiring diagrams

One diagram per station. Red is 3V3 power and dark grey is ground (both run on shared rails beside the board), green is I2C data (SDA), white (grey-outlined) is I2C clock (SCL), yellow is the sensor or servo signal, and orange marks alternate voltages: the servo's 5V VBUS feed. The small number outside each pad is the physical header pin you count to on the board.

Field guide: when it will not work

Sensor not showing up? In the REPL run machine.I2C(0, sda=machine.Pin(0), scl=machine.Pin(1)).scan(). An empty list means wiring, not code. OLED answers as 60 (0x3C), BME280 as 118 (0x76).

Power rules: red to 3V3, black to GND, always. Servos are the exception: red to VBUS (5V).

Board not connecting to the IDE? Make sure the USB cable is a data cable, not a charge-only cable. They look identical. It matters.

Wi-Fi confusion: every board runs its own PicoLab-N network. Check the OLED (or the terminal banner) for which N you are, and join that one.
